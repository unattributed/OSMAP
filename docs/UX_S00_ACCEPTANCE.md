Common tests apply to each case, not instead of its named behavior: missing/
expired session, wrong account, bad/missing CSRF for writes, cross-origin
request, malformed/oversized input, stale revision and interrupted/restarted
operation. Native helper tests add account-grant isolation, resource deadlines,
worker cancellation, key-locked/failure modes and absence of sensitive logs.
Human-reviewed recovery and accessibility cannot be marked passed by an
automated route or screenshot assertion.

The detailed slice catalogue remains the source of helper/runtime, native,
interoperability, assurance and deployment exit criteria that supplement the
individual visual controls. S05-01/03/04 and S06/S07 require actual cryptographic
operations and independent checks, S04-04 requires independent identity policy,
and S10/S11 require fresh target-specific release/deployment evidence. A control
case cannot waive those slice gates.

## Fixture and browser matrix

`src/http/ux_fixtures.rs` exercises real routing/rendering with the existing
test-only in-memory gateway. It exports synthetic, token-redacted HTML only
when `OSMAP_UX_FIXTURE_DIR` is set to an explicit absolute directory. The
normal developer gate executes its route/status/CSP assertions without writing
retained pages. It never constructs a runtime gateway or contacts a mail host.

The original baseline has 15 request states and 45 screenshots at
360/768/1440 CSS pixels in Edge 154.0.4258.37. `source` is intentionally an
ignored source request returning the reader; this proves a missing workflow,
not source-view acceptance. The fixture expansion adds empty mailbox/search,
login error, rejected host and attachment-unavailable states. Future visual
evidence uses all preferences (light/dark/system), both OS schemes for system,
200% zoom, long values, keyboard focus and forced colours. Each newly added
page joins the inventory before its slice can close.

The external Playwright harness serves only the synthetic fixture directory on
loopback, preserves response CSP, aborts outside requests and uses a disposable
browser context. Metrics and screenshots record route, scheme, viewport,
browser version and digest. Test automation may inspect the DOM; production
pages still contain no JavaScript. No real-account browser profile is reused.

Visual acceptance requires inspection, not just screenshot generation. The
baseline revealed a 534-pixel-wide empty drafts table at a 360-pixel viewport,
a reader body misplaced into a narrow grid column, heavy boilerplate status
panels, no icon rail and no actual source or Reply All action. These remain
explicit open implementation work for S01–S03.
